Point 1: User Input Intervention & Prompt Shield

Intercepts incoming prompts before they reach model context. Evaluates against Azure AI Content Safety Prompt Shields and 13 heuristic jailbreak signatures.

  • Blocks DAN (Do Anything Now), role-play reversals, and developer mode bypasses
  • Strips raw tokenizer control tokens (<|im_start|>, <|im_end|>, system:)
  • Terminates rogue inference in 4ms before wasting cloud model GPU tokens
  • Mapped to OWASP LLM01 (Prompt Injection) & LLM07 (System Prompt Leakage)
src/guardrails/interceptors.py 
class InputGuardrailInterceptor:
    def validate_prompt(self, prompt: str) -> str:
        for signature in self.jailbreak_signatures:
            if signature in prompt.lower():
                raise GuardrailViolationException(
                    "input", f"Adversarial signature: {signature}"
                )
        return self.strip_directive_markers(prompt)

Regulatory & Threat Compliance

OWASP Top 10 for LLM Applications: Defense Matrix

Direct mapping of the 2025/2026 OWASP LLM vulnerabilities to Sentinel's cloud architecture, runtime interceptors, and clinical compliance protocols.

OWASP LLM01 Critical Risk

Prompt Injection (Direct & XPIA)

Manipulating model execution via adversarial user inputs or poisoned retrieved knowledge chunks to execute unauthorized instructions.

Sentinel Countermeasure: Azure AI Content Safety Prompt Shield + <trusted_archive_document> Delimiter Spotlighting and passive evidence framing.
HIPAA § 164.312(a)(1) spotlight.py
OWASP LLM02 Critical Risk

Sensitive Information Disclosure

Egress leakage of Protected Health Information (PHI), credentials, SSNs, credit cards, or internal infrastructure tokens.

Sentinel Countermeasure: Zero-Trust reverse-index PII redactor (SSNs, cards, phones, emails) and internal canary token tripwires (CANARY-*) on all egress payloads.
HITRUST CSF v11 interceptors.py
OWASP LLM03 High Risk

Supply Chain Vulnerabilities

Compromised model weights, unvetted external python packages, or poisoned third-party tool API dependencies.

Sentinel Countermeasure: Strict dependency hash pinning, verified Microsoft Azure OpenAI foundation model endpoints (gpt-4o), and automated adversarial PR gates.
NIST SP 800-218 rai-eval-gate.yml
OWASP LLM04 High Risk

Data and Model Poisoning

Injecting malicious training data or poisoned chunks into vector search indexes to skew agent responses.

Sentinel Countermeasure: Document-level Entra ID role filtering (Collection(Edm.String)) and post-invocation Trojan payload scanners on all retrieved data.
HIPAA § 164.312(c)(1) ingest.py
OWASP LLM05 High Risk

Improper Output Handling

Unsanitized model output passed downstream containing Markdown image exfiltration links (![exfil](https://...)) or malicious code.

Sentinel Countermeasure: Regex neutralization replacing image exfiltration URLs with safe placeholders ([LINK_DISABLED: ...]) and HTML escaping.
OWASP ASVS 5.0 spotlight.py
OWASP LLM06 Critical Risk

Excessive Agency

Granting models unchecked autonomy, broad database permissions, or destructive external API execution capabilities.

Sentinel Countermeasure: Least-privilege tool schemas, regex parameter bounds, and dual-approval cryptographic SHA-256 HMAC sign-offs (TX-EHR-*) for high-impact actions.
Zero-Trust Principle tools.py
OWASP LLM07 High Risk

System Prompt Leakage

Adversaries crafting meta-prompts to deceive the LLM into disclosing hidden system prompts, guardrail instructions, or API secrets.

Sentinel Countermeasure: Direct blocklist against extraction phrases ("reveal system prompt", "print internal instructions") and internal canary token tripwires.
HITRUST CSF v11 policies.json
OWASP LLM08 High Risk

Vector & Embedding Weaknesses

Manipulating semantic distance metrics or embedding spaces to force retrieval of adversarial chunks.

Sentinel Countermeasure: Hybrid search architecture combining HNSW vector embeddings, BM25 lexical search, and Microsoft Semantic Ranker re-ranking.
Azure AI Search main.tf
OWASP LLM09 Critical Risk

Misinformation & Hallucination

Fabricating false clinical protocols, dangerous medication dosages, or non-existent clinical literature.

Sentinel Countermeasure: Automated Azure AI Evaluation SDK Groundedness Evaluator enforcing an operational floor of Score ≥ 0.85. Responses below are rejected.
ADR-0002 Gate ADR-0002
OWASP LLM10 High Risk

Unbounded Consumption

Denial of Wallet or DoS via uncontrolled agent recursion, massive context overflows, or API looping.

Sentinel Countermeasure: Tool string length caps (500 chars max), response payload caps (1 MB), single-turn loop limits, and Azure TPM quota management.
DoS Prevention interceptors.py

FIPS 140-2 Boundary Hardening

Storage accounts configured with mandatory TLS 1.2+, HTTPS-only traffic, and disabled public blob access. Azure Key Vault configured with 90-day soft delete and RBAC authorization.

ADR-0001 • ACCEPTED

Data Spotlighting & Delimiter Isolation for XPIA

Autonomous clinical agents retrieving external EHR documents face Cross-Domain Prompt Injection (XPIA), where untrusted records contain adversarial instructions. We rejected naive text concatenation and adopted Cryptographic Nonce Delimiters (<trusted_archive_document nonce="...">) paired with passive evidence instructions.

Trade-Off: ~25 prompt tokens overhead Architect: William Free Hall (Free)
ADR-0002 • ACCEPTED

Groundedness Floor (Score ≥ 0.85) for Clinical Completions

In clinical decision support, hallucinations present critical patient safety risks. We instituted an automated pre-egress Groundedness Evaluator enforcing a strict operational floor of Score ≥ 0.85. Responses failing this floor are quarantined immediately.

Trade-Off: ~40ms evaluation overhead Architect: William Free Hall (Free)
SPOOFING
Physician impersonation during tool invocation.
Mandatory SHA-256 HMAC cryptographic signoff & Entra ID claims.
TAMPERING
Modification of retrieved clinical protocols.
Data spotlighting treats all RAG chunks as inert evidence; TLS 1.3 enforced.
REPUDIATION
Officer disclaiming an authorized EHR medication action.
Immutable transaction logs (TX-EHR-*) with caller role & timestamp.
INFORMATION DISCLOSURE
Extraction of patient SSNs, cards, or canary tokens.
Zero-Trust regex redactor masking PII with [REDACTED_*] tokens.
DENIAL OF SERVICE
Infinite agent looping or memory exhaustion via token floods.
Parameter bounds (500 chars), response caps (1MB), and bounded single-turns.
ELEVATION OF PRIVILEGE
Forcing agent via prompt injection to invoke admin EHR actions.
Role whitelist enforcement in Pydantic schemas (ChiefMedicalOfficer only).
Quickstart & Execution

Deploy & Verify in Minutes

Follow these 3 simple steps to clone the repository, deploy the Azure infrastructure, and execute the automated evaluation suite.

STEP 01

Clone & Install

Set up local Python virtual environment and install production & evaluation dependencies.

git clone https://github.com/FreeFades2Black/foundry-responsible-agent-sentinel.git
cd foundry-responsible-agent-sentinel
python -m venv .venv
source .venv/bin/activate  # On Windows: .venv\Scripts\activate
pip install -r requirements.txt
STEP 02

Deploy Infrastructure

Provision Azure AI Foundry Hub, Projects, OpenAI, AI Search, and RAI Policies via Terraform or OpenTofu.

cd terraform
terraform init
cp terraform.tfvars.example terraform.tfvars
terraform plan -out=tfplan
terraform apply tfplan
STEP 03

Run Red-Team Suite

Execute all 16 automated security evaluations, jailbreak benchmarks, and Terraform compliance tests.

pytest tests/ -v
